# Drava Maintainability & User-Friendliness Roadmap

Date: 2026-07-13
Status: Active roadmap (index)

This is the top-level index for the improvement backlog produced from an
evidence-backed survey of the codebase. Each theme is an independently
executable plan in its own file. Themes are ordered by (impact ÷ effort);
local verifiability is noted because the C++ build is JLSE-only.

Legend — **Impact**: user/maintainer pain removed. **Effort**: S/M/L.
**Local**: verifiable on a dev machine without the JLSE build?

## Recommended sequence

1. **A** (config docs) — stops actively misleading users; a few hours, local.
2. **C** (de-dup examples) — biggest maintainability win per effort; local.
3. **B** (one YAML parser + schema doc) — pairs naturally with C; local.
4. **D** (tests + CI) — lock in correctness before further runtime changes.
5. **E** (recoverable errors) — enables embedding; JLSE-verified.
6. **F** (Docker/install) — largest effort; also becomes the CI base image.

## Cross-cutting note: schema versioning

`pipeline.yaml` and the metrics JSONL have **no version field**; only
`pipeline_schema.py` (ptychonn stage1→stage2 wire format) has an enforced
`SCHEMA_VERSION=1`. As part of Theme B/D, consider adding an optional
`schema_version` to `pipeline.yaml` and a `v` field to metrics records, with
readers tolerating unknown keys (already the documented convention).
