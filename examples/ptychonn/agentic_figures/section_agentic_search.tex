\subsection{Agentic Configuration Search}
\label{sec:agentic-search}

The baseline grid (Section~\ref{sec:baseline}) covered a hand-picked set of
seven configurations.  We now ask a complementary question: given the seven
runtime knobs that \drava{} exposes, how much of the configuration space is
actually \emph{productive}, and can an external agent identify the
productive region from end-to-end latency alone?

\paragraph{Setup.}
The agent is the Bayesian-optimisation tuner from
\texttt{ytopt}~\cite{ytopt}.  It treats \drava{} as a black box, observing
only the scalar end-to-end latency $J(\theta) = T_{e2e}(\theta)$ for each
evaluation.  The configuration vector $\theta$ has seven discrete dimensions:
model batch size $B \in \{128, 256, 512, 1024\}$, per-stage worker thread
counts $T_1 \in \{4, 8, 12, 16\}$ and $T_2 \in \{2, 4, 8, 12\}$, per-stage
callback batch thresholds $C_1 \in \{128, 256, 512, 1024\}$ and
$C_2 \in \{32, 64, 128, 256\}$, ingress rate cap
$R \in \{0, 1000, 2000, 4000\}$\,Hz, and per-stage flush timeout
$W \in \{100, 200, 500\}$\,ms.  The full space contains
$|\Theta| = 12{,}288$ configurations.  The first 12 evaluations are random
seed points; from evaluation 13 onward the surrogate proposes one
configuration per round through the standard \texttt{ask}/\texttt{tell}
interface.  We allow a budget of 64 evaluations, i.e.\ $0.52\%$ of the
search space; each evaluation runs the PtychoNN two-stage benchmark for
$N = 10{,}000$ frames on \TODO{platform}.

\paragraph{Result.}
The best configuration found was $J^{\star} = 3.82$\,s at evaluation~51,
with
$\theta^{\star} = (B{=}128,\, T_1{=}4,\, T_2{=}8,\, C_1{=}128,\,
                   C_2{=}32,\, R{=}0,\, W{=}500)$.
This is a $1.68\times$ improvement over the best of the seven hand-tuned
configurations from Section~\ref{sec:baseline} (6.41\,s).  The total search
wall-time was $938$\,s ($\approx 19$\,s per evaluation), versus an
estimated 65\,h for an exhaustive sweep.

\paragraph{What the agent reveals about the runtime.}
The convergence curve in Figure~\ref{fig:agentic-convergence} is unusually
flat: random sampling found a near-optimum ($3.85$\,s, within $0.8\%$ of
$J^{\star}$) on the very first evaluation, and the best-so-far envelope
moves only modestly thereafter.  This is itself a finding: the optimal
basin in $\Theta$ is broad, not pointlike.  The per-knob conditional
minimum (Figure~\ref{fig:agentic-knobs}) shows why.  Three knobs are
\emph{dominant}---changing them moves the floor by $3$--$4\times$:
\begin{itemize}
  \item $B$: the floor at $B{=}128$ is $3.82$\,s; at $B{=}512$ it is
        $12.1$\,s.
  \item $T_1$: the floor at $T_1{=}4$ is $3.82$\,s; at $T_1{=}16$ it is
        $8.6$\,s.  More Stage~1 threads inflate Stage~1 fps but
        oversaturate Stage~2's input queue.
  \item $R$: any positive rate cap costs $\geq 11$\,s, confirming that
        rate-limited regimes are uniformly inferior for offline workloads.
\end{itemize}
The remaining four knobs ($T_2$, $C_1$, $C_2$, $W$) are essentially
\emph{flat}: the spread of the conditional minimum across their settings
is below $0.5$\,s.  The top-10 configurations
(Figure~\ref{fig:agentic-top}) confirm this directly: all ten share
$B{=}128$, $T_1{=}4$, and $R{=}0$, but spread freely across all four
discrete values of $T_2$ and three of four values of $C_1$.  The runtime
therefore exposes a configuration space whose productive degrees of
freedom are few; the operator must get $B$, $T_1$, and $R$ right and the
remaining knobs are forgiving.

\paragraph{Cost of the search.}
Because each evaluation reuses the same warm benchmark infrastructure, the
agentic search is a single offline job rather than a re-deployment loop.
The runtime overhead it observes is exactly the per-evaluation overhead
defined by Equation~\ref{eq:overhead-pct} from
Section~\ref{sec:observability}: no additional probes are inserted for the
agent's benefit, and the same lock-free counters that drive the operator
dashboard drive the search.
